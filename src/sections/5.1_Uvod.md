# Monitori (SW)

## Uvod

**Šta je `Signal-and-Wait` disciplina?**

Kod `Signal-and-Wait (SW)` discipline, nit koja unutar monitorske procedure pozove `cond.signal()` napušta monitor i odlazi u red čekanja za ulazak u monitor (`entry queue`), dok signalizirana nit odmah ulazi u monitor i nastavlja izvršavanje od mesta na kom je pozvala `cond.wait()`. Sve ostalo - monitorske procedure, uslovne promenljive i monitorska invarijanta - isto je kao kod `Signal-and-Continue` discipline opisane u prethodnoj glavi.

**U čemu je razlika u odnosu na `Signal-and-Continue` disciplinu?**

1.  Signalizirana nit odmah dobija kontekst, pa uslov zbog kog je nit bila blokirana i dalje važi kada se nit probudi. Zato je dovoljno da se uslov proveri jednom, sa `if (uslov) cond.wait();`, dok kod `SC` discipline uslov mora da se proverava u petlji, sa `while (uslov) cond.wait();`.
2.  Poziv `cond.signal()` napušta monitor, pa se posle njega ne sme računati na to da su unutrašnje promenljive monitora ostale nepromenjene. Zbog toga se `signal()` najčešće poziva kao poslednja naredba monitorske procedure.
3.  Operacija `cond.signalAll()` ne postoji, jer kontekst može da se preda samo jednoj niti.

**Kako se implementira monitor sa `Signal-and-Wait` disciplinom pomoću semafora?**

```cpp
class SW_Monitor {
	Sem mutex = 1;
	queue<Sem&> qWait;
	void enter() {
		wait(mutex);
	}
	void leave() {
		if (! qWait.empty()) {
			signal(qWait.pop());
		} else {
			signal(mutex);
		}
	}
	class cond {
		priority_queue<Sem&, int> qCond;
		void wait(int rank = 0) {
			Sem privs = 0; // private semaphore
			qCond.push(privs, rank);
			if (! qWait.empty()) {
				signal(qWait.pop());
			} else {
				signal(mutex);
			}
			wait(privs);
		}
		void signal() {
			if (! qCond.empty()) {
				Sem privs = 0; // private semaphore
				qWait.push(privs);
				signal(qCond.pop());
				wait(privs);
			}
		}
		bool queue() {
			return qCond.size() > 0;
		}
		bool empty() {
			return qCond.empty();
		}
		int minrank() {
			return qCond.peek().rank; 
		}
	};
};
```
